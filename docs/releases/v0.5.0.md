# VaultDMS v0.5.0 — blueprint §6 — §12 shipped

Date: 2026-05-13
Branch: `feat/passkeys` → `main`
Tag: `v0.5.0` (annotated on the merge commit)

This release packages 24 days of work spanning every blueprint section
from §6 through §12 into one named bundle. The branch is misnamed —
"passkeys" was the first feature in the wave and the name stuck — but
the content is broad. Future releases will use a less specific branch
name.

## Headline features

**Authentication + identity (§8, §13.5)**
- WebAuthn / passkeys end-to-end (ADR 0061) — registration, login,
  step-up grants, virtual-authenticator tests.
- LDAP / AD direct-bind with group sync (ADR 0062).
- Full MFA surface — TOTP / email OTP / SMS OTP / push approve / WebAuthn
  with strongest-first selection (ADR 0063).

**Documents (§10)**
- Approval routing patterns (sequential / parallel / N-of-M, ADR 0064).
- WOPI co-authoring against OnlyOffice (ADR 0065).
- Threaded comments with reactions (ADR 0066).
- Annotation layers — highlight, comment, redaction-candidate (ADR 0067).
- Lightweight tasks (ADR 0068).

**Search + intelligence (§7, §11)**
- Faceted search with URL-state + saved filter sets (ADR 0082).
- Permission-filtered search with 5s debounced reindex + propagation-lag
  SLI dashboard (ADR 0083).
- Grouped autocomplete suggester (ADR 0084).
- Saved-search alerts with Temporal scheduled workflows + per-channel
  preferences (ADR 0085).
- Notification preferences matrix + snooze + DND + digest (ADR 0086).
- Federated cross-tenant admin search with audit-on-every-outcome
  (ADR 0069).
- NER pipeline: regex + SpaCy + opt-in LLM (ADR 0078).
- Redaction review queue + burn-in worker (ADR 0079).
- RAG with permission-filtered retrieval + workspace AI settings
  (ADR 0080).
- LiteLLM routing with per-tenant provider/key/budget (ADR 0081).
- Active learning pipeline (ADR 0060).
- Classification corrections (ADR 0059).
- Anomaly detection (ADR 0058).
- OCR quality scoring + admin queue (ADR 0057).
- Translation pipeline (ADR 0056).
- Document Q&A with SSE streaming (ADR 0055).
- Compliance PII / PHI detection (ADR 0054).
- Smart routing — three-strategy folder suggestions (ADR 0053).
- Auto-tag suggestions (ADR 0052).

**Signature (ADRs 0070-0073)**
- eIDAS QES via Swisscom / Intesi / InfoCert.
- DocuSign + Adobe Sign third-party connectors.
- PAdES-LTV validator with DSS embed.
- Mobile + in-person signing modes.

**API surface (§12)**
- GraphQL read API (ADR 0074).
- gRPC bulk import / export (ADR 0075).
- Customer-facing webhooks with HMAC-SHA256 + 5s/30s/2m/15m/1h/6h
  backoff + DLQ + redeliver (ADR 0076). Acceptance verified
  end-to-end: 75 ms test-send, signature reproduced by Python
  sample, retry schedule matched, DLQ + redeliver clean.
- Per-tenant event streaming on NATS with operator-mode JWT issuance
  + polling fallback + SSE live tail (ADR 0077).
- Email ingestion (ADR 0087): IMAP backend end-to-end with KEK
  password encryption and document-row materialisation. Microsoft 365
  + Gmail + storage-blob version upload deferred to §12.5c.

**Frontend (across the wave)**
- Migration to canonical shadcn/ui — Phase 1 foundation through
  Phase 3d's 13 routes swept. ~78 Button + 35 Input + 13 Select +
  43 Avatar/Badge consumers ported to canonical primitives. Drawer
  (vaul), Calendar, Combobox, Tabs, Sheet, Tooltip, ConfirmDialog,
  DropdownMenu canonical wrappers introduced.
- Dashboard / auth shell / workspaces / document detail redesigns.
- Admin tile sweep — every panel re-skinned, new tiles for
  Webhooks, Event streaming, Email ingestion, AI provider, NER
  config, redaction review, etc.

## Migrations

41 document-service migrations (000012 → 000041). Each is forward-only
in practice — `make migrate-down SERVICE=document` exists per-table
but is for emergencies. Run against a staging DB first; once a prod
runs `make migrate-up` the rollback is restore-from-backup.

Notable new tables:
- `webhook_subscriptions` + `webhook_deliveries`
- `tenant_event_tokens`
- `email_ingestion_configs` + `email_messages`
- `tenant_llm_config`, `ner_config`, plus per-pipeline review tables
- `webauthn_credentials` + `step_up_grants`
- `saved_search_subscribers` + alert-state columns
- `platform_admins` + `federated_search_audit`
- 13 intelligence-pipeline schema migrations (auto_tag, smart_route,
  compliance, qa_history, translation, ocr_quality, anomaly,
  classify-corrections, active-learning, NER, redaction, RAG,
  litellm).

## Test posture

`go test -count=1 ./services/... ./pkg/...` green across all 25
packages with tests. Architecture invariants enforced:
- Phase C5 (outbox-only NATS publish, §4.7)
- Phase C4 (request-scoped context in handlers, §15.3)
- routes.yaml ↔ kong.yaml mirror

Four pre-existing test failures were caught and fixed in this cut:
- WOPI handler `context.Background` violation (now request-scoped)
- Kong / routes drift on two ADR-0083/0069 endpoints (added)
- Architecture test over-strict on the §12.3 eventstream mirror
  (whitelisted the package the same way `pkg/database` is)
- TSP `TestState_TamperDetected` 1-in-16 flake (deterministic tamper)

## Known follow-ups (queued, not blocking the cut)

- **§12.5c** — Microsoft 365 + Gmail real backend HTTP, storage-blob
  upload step so email attachments enter OCR/classify pipelines,
  rule-based folder mapping. Documented in ADR 0087.
- **NATS operator-mode switch** — ADR 0077 stages the deploy-time
  rotation behind `VAULTDMS_NATS_OPERATOR_MODE=true`. Today's
  no-auth NATS still works because the runtime issues JWTs that
  become valid the moment the server flips.
- **ADR number collision** — the blueprint reserved 0078 for email
  ingestion but the codebase took 0078 for the NER pipeline before
  this wave. Email ingestion uses 0087 instead; explicitly documented
  inside the ADR.

## Upgrade checklist

For an operator merging this to main:

1. `make migrate-up SERVICE=document` (and every other service) on a
   staging DB first. Confirm none fail.
2. Rebuild and roll: `docker compose up -d --build` end-to-end. Watch
   container health.
3. Re-run the Playwright suite against the staging URL.
4. Tag the merge commit as `v0.5.0` (signed annotation), push to
   origin, draft a GitHub release with this file as the body.
